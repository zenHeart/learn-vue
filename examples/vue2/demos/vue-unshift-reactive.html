🔍 Vue unshift 响应式问题与解法

⚠️ 场景一：数组直接索引赋值，视图不更新 问题

直接通过索引设置数组元素，Vue 2 无法检测到变化。

#{{i}} {{item}} old
// ❌ 错误做法 — Vue 2 响应式失效 this.items[0] = 'New'; // 视图不更新！ // ✅ 正确做法 1 — Vue.set Vue.set(this.items, 0, 'New'); // ✅ 正确做法 2 — 数组替换（触发整体更新） this.items = ['New', ...this.items];

✅ 场景二：unshift 添加数据 正确用法

unshift 是 Vue 2 响应式系统能检测到的数组方法，直接使用即可触发更新。

#{{i}} {{item.name}} {{item.isNew ? 'NEW' : 'old'}}
最近操作：{{lastAction}}
// ✅ unshift — Vue 2 响应式系统能检测到，会触发更新 this.items.unshift({ name: 'New Item', isNew: true }); // ✅ splice(0,0,item) — 同效，也是响应式方法 this.items.splice(0, 0, { name: 'New Item', isNew: true }); // ✅ 数组整体替换 — 推荐用于需要强制更新或 Vue 3 this.items = [{ name: 'New Item', isNew: true }, ...this.items];

⚠️ 场景三：嵌套对象中的 unshift 边界情况

如果数组中的对象属性本身不是响应式的，添加后内部数据也不会是。

{{group.label}}
#{{ii}} {{item}}
⚠️ 注意：如果 group.children 一开始是空数组 `[]`，后赋值为响应式数组 `['a','b']`，Vue 无法检测到这种"从无到有"的引用替换。解决方案：初始化时使用响应式容器，或整体替换数组。

🚀 场景四：Vue 3 Proxy vs Vue 2 defineProperty Vue 3

Vue 3 使用 Proxy 替代 defineProperty，直接索引赋值在多数情况下可以触发更新。

// Vue 2 — Object.defineProperty // ✅ unshift / splice / push / pop — 响应式 // ❌ arr[0] = x — 不响应 // ❌ arr.length = 0 — 不响应 // Vue 3 — Proxy // ✅ unshift / splice / push / pop — 响应式 // ✅ arr[0] = x — 响应（但要确保数组是响应式 Proxy 对象） // ❌ arr.length = 0 — 仍然不直接响应，需通过方法操作

🧠 核心原理

┌─────────────────────────────────────────────────────┐ │ Vue 2 响应式系统 │ ├─────────────────────────────────────────────────────┤ │ Object.defineProperty 只能监听： │ │ ✅ 数据属性的 get/set 访问 │ │ ✅ push/pop/shift/unshift/splice 等方法 │ │ ❌ 数组直接索引赋值 arr[i] = x │ │ ❌ 直接修改 arr.length │ ├─────────────────────────────────────────────────────┤ │ Vue 3 响应式系统 │ ├─────────────────────────────────────────────────────┤ │ Proxy 可以监听： │ │ ✅ 上述所有操作 │ │ ✅ 数组直接索引赋值 arr[i] = x（通过 handler） │ │ ⚠️ arr.length = 0 仍需通过方法触发 │ └─────────────────────────────────────────────────────┘
