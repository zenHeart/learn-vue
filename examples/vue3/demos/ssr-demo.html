SSR 渲染模式对比 — 交互演示

深入理解 Server-Side Rendering vs Client-Side Rendering vs Static Site Generation

三种渲染模式核心差异

选择合适的渲染模式是应用架构的第一步。以下是核心对比：

维度CSRSSRSSG
首屏渲染慢 需下载 JS快 直接显示 HTML快 直接显示 HTML
SEO差 无内容好 完整 HTML好 完整 HTML
服务器负载低 静态文件中 实时渲染极低 CDN 缓存
交互性需 hydration需 hydration需 hydration
适用场景管理后台、SPA内容型、电商、社交博客、文档、落地页

CSR 渲染流程

1 Browser: 请求空白 HTML（含 JS 链接）
2 Browser: 下载 JS Bundle（可能 500KB+）
3 Browser: Vue 执行，创建虚拟 DOM
4 Browser: 挂载到 #app，用户看到内容 
// index.html - 空白容器
<div id="app"></div>
<script type="module" src="/src/main.js"></script>

// main.js - CSR 入口
import { createApp } from 'vue'
import App from './App.vue'
createApp(App).mount('#app')   // 白屏 → 有内容

SSR 渲染流程

1 Server: 接收请求，运行 Vue 组件 → 输出 HTML 字符串
2 Server: 返回完整 HTML（含预渲染内容）
3 Browser: 显示首屏内容（用户立即看到）
4 Browser: 下载 JS + Hydration（变为可交互） 
// server.js - SSR 入口
import { createSSRApp } from 'vue'
import App from './App.vue'
import { renderToString } from 'vue/server-renderer'

async function handleRequest(req, res) {
  const app = createSSRApp(App, { url: req.url })
  const html = await renderToString(app)  // Vue → HTML 字符串
  res.send(`<!DOCTYPE html>...${html}...</html>`)
}

SSG 渲染流程

1 Build: 预渲染所有页面为静态 HTML
2 CDN: 上传静态文件到全球 CDN
3 Browser: 直接获取 HTML（毫秒级）
4 Browser: Hydration 后变为可交互 
// nuxt.config.ts - Nuxt SSG 配置
export default defineNuxtConfig({
  routeRules: {
    '/**': { prerender: true }  // 所有页面预渲染
  }
})

# 构建命令
$ npx nuxt generate   // 输出 .output/public/

什么是 Hydration？

Hydration（水合）是 SSR 后的关键步骤：服务端输出的静态 HTML 与客户端 Vue 实例"结合"，让页面从静态展示变为可交互应用。

1 Server: renderToString() → 生成 HTML 字符串
2 Network: HTML 传输到浏览器，立即显示内容
3 Browser: 下载 JS bundle
4 Hydration: Vue 遍历现有 DOM，建立响应式绑定
5 Done: 页面完全可交互

Hydration 代码示例

// client.js - 使用 createSSRApp 而非 createApp
import { createSSRApp } from 'vue'
import App from './App.vue'

// 必须使用 createSSRApp，告知 Vue 这是 SSR 后 hydration
const app = createSSRApp(App, { ... })

// mount 后，Vue 会"接管"已存在的 DOM，而不是创建新的
app.mount('#app', true)  // 第二个参数 = hydrate

为什么必须用 createSSRApp？

API用途DOM 行为
createApp纯 CSR清空 #app，创建全新 DOM
createSSRAppSSR hydration复用 #app 中已有 DOM，建立响应式

⚠️ 如果用 createApp 代替 createSSRApp，服务端渲染的 HTML 会被清空重绘，导致闪烁 + hydration mismatch

什么是 Hydration Mismatch？

服务端渲染的 HTML 与客户端渲染结果不一致时，会发生 hydration mismatch。Vue 会尝试自动修复，但可能导致闪烁或控制台警告。

❌ Mismatch 示例：组件内使用随机数

服务端输出： 用户ID: 842719053
客户端输出： 用户ID: 391204756 ← 不一致！
// ❌ 错误：每次渲染产生不同结果
const userId = Math.random()   // 服务端、客户端值不同 → Mismatch

// ✅ 正确：在客户端 only 执行
import { ref, onMounted } from 'vue'
const userId = ref(null)
onMounted(() => { userId.value = Math.random() })  // 仅客户端执行

❌ Mismatch 示例：访问 window/document

// ❌ 错误：在 setup 顶层访问 window
const width = window.innerWidth   // 服务端没有 window → Error

// ✅ 正确：使用 useWindowSize 或 onMounted
const width = ref(window.innerWidth)   // 仅客户端执行

❌ Mismatch 示例：日期格式化

服务端（UTC）： 2026-03-27 00:00:00
客户端（+8）： 2026-03-27 08:00:00 ← 时区差异
// ❌ 错误：依赖本地时区
const dateStr = new Date().toLocaleString()  // 时区不同 → Mismatch

// ✅ 正确：统一使用 UTC 或让用户设置时区
const dateStr = new Date().toUTCString()

常见 Mismatch 原因

原因解决方案
随机值（Math.random, Date.now）仅在 onMounted/客户端执行
window/document/globalThis用 process.client 判断或 onMounted
浏览器特有 API（localStorage 等）条件保护，SSR 时返回默认值
时区/语言差异统一 UTC，格式化放客户端
v-if 条件不一致确保服务端/客户端渲染条件相同
Pinia/Vuex store 初始化不一致使用 snapshotTheron 序列化

Mismatch 调试技巧

// 1. Vue DevTools - 开启 hydration 插件
// 2. console 警告会显示具体不一致的组件
// 3. 使用 <ClientOnly> 包裹浏览器专属组件（Nuxt）

<template>
  <ClientOnly>
    <BrowserOnlyComponent />  <!-- 服务端跳过 -->
  </ClientOnly>
</template>

// 4. 禁用 hydration（最后手段）
<div :data-allow-mismatch="true">
  <Suspense />
</div>

Nuxt.js 项目结构

Nuxt 是 Vue SSR 最流行的框架，自动处理代码差异、路由、状态序列化等复杂问题：

📁 my-nuxt-app/
├── nuxt.config.ts # 框架配置
├── app.vue # 应用根组件
├── pages/ # 路由页面（基于文件）
│ ├── index.vue # → /
│ └── blog/[id].vue # → /blog/:id
├── components/ # 自动导入组件
├── composables/ # 可复用逻辑
├── server/ # 服务端 API
│ └── api/hello.ts # → /api/hello
├── public/ # 静态资源
└── .output/ # 构建输出
# pages 目录自动生成路由，无需手动配置

Nuxt 渲染模式配置

// nuxt.config.ts
export default defineNuxtConfig({
  // 混合渲染策略
  routeRules: {
    // 静态生成，构建时渲染
    '/':               { prerender: true },

    // ISR，CDN 缓存后后台更新
    '/blog/**':         { swr: 3600 },

    // 服务端渲染，实时数据
    '/product/**':     { ssr: true },

    // 客户端渲染，SPA
    '/dashboard/**':   { ssr: false }
  }
})

Nuxt 数据获取

// pages/blog/[id].vue
<script setup="">
  // useAsyncData - 服务端执行，客户端复用（避免重复请求）
  const { data, pending, error } = await useAsyncData(
    'post',
    () => $fetch(`/api/posts/${route.params.id}`)
  )

  // useFetch - useAsyncData 的简化版
  const { data } = await useFetch('/api/posts')

  // 仅客户端执行（如点赞数、浏览量）
  const likes = ref(0)
  onMounted(async () => {
    likes.value = await $fetch('/api/likes')
  })
</script>

Nuxt 环境判断

// 服务端专属（只在 server/ 目录或 setup 顶部执行）
process.server   // true when SSR

// 客户端专属（只在浏览器执行）
process.client   // true when browser

// 示例：条件执行
if (process.server) {
  // 仅服务端：访问数据库、读取文件等
  data = await db.query('SELECT * FROM posts')
}

// 示例：组件内判断
<script setup="">
  const showModal = ref(false)
  if (process.client) {
    // 客户端：读取 localStorage
    showModal.value = localStorage.getItem('showModal') === 'true'
  }
</script>

process.client vs process.server

Nuxt 自动注入这两个全局变量，用于区分代码执行环境：

变量服务端客户端典型用途
process.servertruefalse数据库访问、文件读取
process.clientfalsetruelocalStorage、DOM 操作

onMounted — 客户端独占

<script setup="">
  import { ref, onMounted } from 'vue'

  // ✅ 正确：onMounted 仅在客户端执行
  const screenWidth = ref(0)
  onMounted(() => {
    screenWidth.value = window.innerWidth
  })

  // ✅ 正确：process.client 条件判断
  const isMobile = ref(false)
  if (process.client) {
    isMobile.value = window.matchMedia('(max-width: 768px)').matches
  }
</script>

Pinia 状态序列化

服务端渲染时 Pinia store 会被序列化（devalue）传到客户端，防止状态丢失：

// stores/user.ts
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    name: 'Guest',
    preferences: { theme: 'dark' }
  }),
  // ⚠️ 不要在 state 中放无法序列化的对象
  // ❌ error: Date 对象、window、DOM 引用
  // ✅ 正确：只放纯数据
})

⚠️ Pinia 状态必须可序列化。Map、Set、Date、class 实例等无法通过 devalue 序列化，会导致运行时错误。

Vite SSR 开发提示

// vite.config.ts - SSR 插件
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  // 标记服务端依赖，防止打包到客户端
  ssr: {
    noExternal: ['vue', 'vue-router']
  }
})

// 构建 SSR bundle
$ vite build --ssr src/entry-server.js
$ vite build --ssr src/entry-client.js
