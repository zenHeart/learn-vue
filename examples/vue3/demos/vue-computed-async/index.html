演示1：Computed 依赖异步数据
// 模拟异步获取用户数据
const user = ref(null)

// Computed 依赖 user.value
const greeting = computed(() => {
  return user.value 
    ? `Hello, ${user.value.name}!`
    : '加载中...'
})

// 异步请求
fetchUser().then(data => {
  user.value = data  // ✅ 触发 computed
})

演示2：Computed 闭包建立时机
// 问题：setup 执行时 computed 建立
// 但此时 user.value === null
const user = ref(null)

// ✅ Computed 自动追踪 user.value
const displayName = computed(() => {
  return user.value?.name ?? '匿名'
})

// 异步后赋值
setTimeout(() => {
  user.value = { name: 'Alice' }
  // ✅ 正确触发更新，因为 ref 引用不变
}, 1000)
user.value: {{ closureUser ? closureUser.name : 'null (等待加载...)' }}
computed displayName: {{ displayName }}
状态: {{ closureStatus.toUpperCase() }}
⚠️ 关键点
Computed 建立时捕获的是 ref 的引用，而非值。只要 ref 引用不变，后续赋值就能触发更新。
演示3：Watch 与 Computed 的区别
// Computed：派生值，有缓存
const filteredItems = computed(() => {
  console.log('Computed 计算中...')
  return items.value.filter(...)
})

// Watch：执行副作用，无缓存
watch(items, (newVal, oldVal) => {
  console.log('Watch 执行中...')
  // 执行副作用，如保存到存储
}, { deep: true })

演示5：嵌套异步导致的时序问题
// 问题场景：嵌套异步依赖
const entity = ref(null)
const relatedData = ref(null)

// Computed 依赖多个响应式数据
const fullInfo = computed(() => {
  if (!entity.value || !relatedData.value) {
    return '加载中...'
  }
  return { ...entity.value, ...relatedData.value }
})

📚 核心要点总结
场景 问题 解决方案
Computed 初始值为 null 直接访问属性报错 使用可选链 ?. 和空值合并 ??
异步数据更新后不触发 赋值方式错误 确保使用 .value = newValue
需要执行副作用 Computed 不应执行副作用 使用 watch 或 watchEffect
修改数组内容 直接 push 可能不触发 使用响应式代理的方法或替换数组
需要访问旧值 Computed 无法访问旧值 使用 watch 的第二个参数
