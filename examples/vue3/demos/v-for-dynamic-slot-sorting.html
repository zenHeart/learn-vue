🔍 问题分析

使用 index 作为 key 时，排序后 Vue diff 算法认为 key=0、key=1 的节点仍然存在，于是复用了组件实例。但此时 index=0 的数据已经从 {id:1, color:'red'} 变成了 {id:2, color:'green'}，导致显示错乱。

// ❌ 错误代码：使用 index 作为 key
<div v-for="(item, index) in items" :key="index">
  <component :is="item.component" :data="item" />
</div>

✅ 方案一：使用稳定的唯一 Key

使用 item.id 作为 key，确保每个组件实例与数据一一对应。

✅ 正确做法：每次切换到该 Tab 时数据会重置为初始顺序。排序后每个组件正确显示对应的数据和颜色。
id={{ item.id }}
{{ item.name }}
{{ item.componentName }}
实例 #{{ item.instanceId }} | color={{ item.color }}

✨ 解决方案

使用 item.id 作为 key。排序后，Vue diff 能正确识别 id=1 和 id=2 的节点位置发生了变化，并正确移动组件实例。每个实例都能正确渲染对应的数据。

// ✅ 正确代码：使用唯一 id 作为 key
<div v-for="item in items" :key="item.id">
  <component :is="item.component" :data="item" />
</div>

✅ 方案二：Computed 中先排序再遍历

在 computed 中完成排序，确保遍历的数据顺序稳定，组件实例不复用问题。

✅ 正确做法：通过切换升序/降序来改变排序，每次排序后数据完全更新，组件实例不复用。
id={{ item.id }}
{{ item.name }}
{{ item.componentName }}
实例 #{{ item.instanceId }} | color={{ item.color }}

✨ 解决方案

在 computed 中返回排序后的新数组 [...items].sort(...)。这样每次排序后，v-for 遍历的是全新的数组，Vue 会认为这是全新的数据，创建新的组件实例。

// ✅ 正确代码：computed 中排序
const sortedItems = computed(() => {
  return [...items.value].sort((a, b) =>
    sortAsc.value ? a.id - b.id : b.id - a.id
  )
})

// 模板中遍历 sortedItems
<div v-for="item in sortedItems" :key="item.id">
  <component :is="item.component" />
</div>

✅ 方案三：动态 :is + 直接 Props 传递

通过 props 直接传递数据给动态组件，避免作用域插槽的闭包捕获问题。

✅ 正确做法：每次切换到该 Tab 时数据会重置为初始顺序。排序后组件正确显示，且没有作用域插槽的闭包问题。
id={{ item.id }}
{{ item.name }}
{{ item.componentName }}
实例 #{{ item.instanceId }} | color={{ item.color }}

✨ 解决方案

不使用作用域插槽，而是通过 props 直接传递 :name、:color、:item-id。这样数据流清晰明确，排序后组件正确更新，不会出现闭包捕获旧引用的问题。

// ✅ 正确代码：动态组件 + 直接 props
<component
  :is="item.component"
  :name="item.name"
  :color="item.color"
  :item-id="item.id"
/>

🔑 Key 选择指南

了解不同 key 类型的行为和适用场景，避免常见的 key 使用错误。

Key 类型 可用性 说明 排序后行为
item.id 推荐 数据的唯一标识，稳定且有意义 ✅ 正确复用和移动组件实例
item.uuid 推荐 业务生成的唯一 ID ✅ 正确复用和移动组件实例
index 禁止 数组索引，随排序改变 ❌ 错误复用组件实例
Math.random() 禁止 每次渲染都是新值 ❌ 完全破坏 Vue 复用机制
item.id + index 慎用 复合 key，形式复杂 ⚠️ 可能导致意外行为 
// ❌ 错误示例
<div v-for="(item, index) in items" :key="index">  // index 会变化！
<div v-for="item in items" :key="Math.random()">  // 永远不同！

// ✅ 正确示例
<div v-for="item in items" :key="item.id">  // 稳定唯一
<div v-for="item in items" :key="item.uuid">  // 业务唯一 ID

v-for + 动态组件 Checklist

✅ 最佳实践

v-for 使用数据的唯一标识（id/uuid）作为 key
避免在作用域插槽中捕获易变的索引变量
优先使用 computed 排序后再遍历
优先通过 props 传递数据，而不是作用域插槽
组件实例需要保持状态时，确保 key 的稳定性
