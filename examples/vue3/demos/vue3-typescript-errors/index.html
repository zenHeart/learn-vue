🔧 Vue 3 TypeScript 常见报错及解决方案

1. Type 'unknown' is not assignable to type 'xxx'
reactive/ref 的类型推断导致 unknown 类型

💡 原因分析

Vue 3 的响应式函数会根据初始值推断类型。如果 ref/reactive 没有初始值或初始值为 null/undefined，TypeScript 会推断为 unknown，导致无法赋值给具体类型。

❌ 错误示例
// ref 初始值为 null
const data = ref(null)
data.value = 'hello'  // TS2345

// reactive 空对象
const state = reactive({})
state.name = 'Tom'  // TS2339
✅ 解决方案
// 泛型声明具体类型
const data = ref<string | null>(null)
data.value = 'hello'  // ✅ 正常

// reactive 使用泛型
const state = reactive<{name: string}>({
  name: 'Tom'
})
state.name = 'Alice'  // ✅ 正常

2. Property does not exist on type
模板 ref 的类型未正确定义

💡 原因分析

模板 ref 需要显式声明类型，Vue 无法自动推断 .vue 文件组件实例的类型。需要使用 InstanceType<typeof Component> 来获取组件类型。

❌ 错误示例
// 没有声明类型
const myRef = ref(null)
myRef.value.someMethod()  // TS2339

// DOM ref 未指定类型
const inputEl = ref(null)
inputEl.value?.focus()  // TS
✅ 解决方案
// DOM 元素指定 HTML 类型
const inputEl = ref<HTMLInputElement | null>(null)
inputEl.value?.focus()  // ✅

// 子组件使用 InstanceType
import Child from './Child.vue'
const childRef = ref<InstanceType<typeof Child> | null>(null)

3. Cannot find module or its corresponding type declarations
组件类型声明缺失或 shims-vue.d.ts 配置问题

💡 原因分析

TypeScript 默认不识别 .vue 文件，需要通过 shims-vue.d.ts 声明模块类型。Vite 项目还需要配置 vite/client 类型。

❌ 缺少配置
// 项目根目录缺少 shims-vue.d.ts
// 或 tsconfig.json 未包含

// 导入 .vue 文件时报错
import MyComponent from './MyComponent.vue'
// TS2307: Cannot find module
✅ 解决方案
// shims-vue.d.ts
declare module '*.vue' {
  import Component from 'vue'
  const component: Component
  export default component
}

// tsconfig.json
{
  "include": ["src/**/*.ts", "src/**/*.vue"],
  "types": ["vite/client"]
}
4. Module has no exported member
Vue 2 到 Vue 3 的 API 导入差异

💡 原因分析

Vue 3 重构了大量 API，某些 Vue 2 的导入在 Vue 3 中已不存在或已重命名。

❌ Vue 2 写法
// Vue 2 导入方式
import Vue from 'vue'
Vue.mixin({})
Vue.extend({})

// Vue 2 过滤器
import 'vue2-filters'
✅ Vue 3 正确写法
// Vue 3 Composition API
import {
  ref,
  reactive,
  computed,
  watch
} from 'vue'

// 插件使用 createApp
import { createApp } from 'vue'
const app = createApp({})
app.mount('#app')
5. Props 类型推断问题
defineProps 的类型推断不正确

💡 原因分析

使用基于类型的 defineProps 声明时，可选属性可能推断为 undefined。Vue 3.4+ 推荐使用 withDefaults 提供默认值。

❌ 问题写法
// 可选属性推断不准确
const props = defineProps<{
  name: string
  count?: number
}>()
// props.count 可能是 undefined
console.log(props.count + 1) // TS
✅ 解决方案
// Vue 3.4+ withDefaults
const props = withDefaults(
  defineProps<{
    name: string
    count?: number
    items?: string[]
  }>(),
  {
    count: 0,
    items: () => []
  }
)
console.log(props.count + 1) // ✅

6. Volar 工具链配置问题
Volar/vue-tsc 版本不兼容或配置错误

💡 原因分析

Volar 是 Vue 3 的官方 VS Code 扩展，需要与 vue-tsc 配合使用。如果类型提示失效或报错，检查版本和配置。

❌ 常见问题
// Volar 版本过旧
// vue-tsc 未安装
// tsconfig.json 配置错误

// 错误示例配置
{
  "moduleResolution": "node"  // ❌
  "types": []  // ❌ 缺少 vite/client
}
✅ 正确配置
// 安装 vue-tsc
npm install -D vue-tsc

// tsconfig.json
{
  "compilerOptions": {
    "moduleResolution": "bundler",
    "types": ["vite/client"],
    "skipLibCheck": true
  }
}

// package.json 添加检查脚本
{
  "scripts": {
    "type-check": "vue-tsc --noEmit"
  }
}
7. 模板 ref 类型错误
模板 ref 需要显式声明组件实例类型

💡 原因分析

模板 ref 需要通过 InstanceType<typeof Component> 获取组件类型，子组件需通过 defineExpose 暴露方法。

❌ 错误示例
// 子组件未暴露方法
// <script setup>
const count = ref(0)
// ❌ 没有 defineExpose

// 父组件
const childRef = ref(null)
childRef.value?.increment() // TS
✅ 解决方案
// 子组件暴露方法
const count = ref(0)
const increment = () => count.value++

defineExpose({ count, increment })

// 父组件正确引用
import Child from './Child.vue'
const childRef = ref<InstanceType<typeof Child>>(null)
childRef.value?.increment()  // ✅
8. watch/watchEffect 回调类型错误
watch 多个数据源时类型推断不准确

💡 原因分析

watch 监听多个数据源时，newValues 和 oldValues 都是数组类型，TypeScript 无法准确推断每个元素的类型。

❌ 问题写法
// 多个数据源类型不明
watch([count, name], (newValues) => {
  // newValues 类型: unknown[]
  console(newValues[0] + 1) // TS
})

// 单个源但未声明类型
watch(count, (newVal) => {
  // 可能推断为 unknown
})
✅ 解决方案
// 元组形式明确类型
watch(
  [count, name],
  ([newCount, newName], [oldCount, oldName]) => {
    console(newCount + 1)  // ✅
  }
)

// 单个源显式声明
watch(count, (newVal: number) => {
  console(newVal + 1)  // ✅
})
