Vue 3 whitespace 处理策略

compilerOptions.whitespace: 'condense' vs 'preserve' 可视化演示

什么是 whitespace 选项？

Vue 3 编译器选项，控制模板中空白字符（空格、换行、制表符）的处理方式。

Vue 2 默认： whitespace: 'preserve' — 保留所有空白符
Vue 3 默认： whitespace: 'condense' — 压缩连续空白为单个空格

三种模式对比

模式 行为 场景
condense 连续空白压缩为 1 个空格 Vue 3 默认，适合大多数项目
preserve 保留原始空白符 Vue 2 迁移、pre 标签、严格空白格式

最常见的问题：内联元素换行间距

当 <button> 或 <span> 在模板中换行书写时，condense 模式会产生可视间距：

<button>按钮一</button>
<button>按钮二</button>
↓ 渲染后 ↓
按钮一(空格)按钮二 ← 多余的空格被浏览器渲染为间距

快速开始

// vite.config.js
import vue from '@vitejs/plugin-vue'

export default {
  plugins: [vue({
    compilerOptions: {
      whitespace: 'preserve'  // 恢复 Vue 2 行为
    }
  })]
}

或使用下面的演示切换模式，观察 DOM 结构变化。

在 condense 模式下，换行被压缩但仍产生空格节点。CSS flex/grid 是最干净的解决方案。

当前模式: preserve

内联按钮组

preserve 模式会保留模板中的原始换行符，浏览器仍会产生间距（这是 HTML/CSS 的默认行为）。

preserve 只影响编译器行为，浏览器内联格式化上下文的间距不受此控制。

两种模式的本质区别

condense（默认）

<button>一</button> <button>二</button>

连续空白 → 单个空格

preserve

<button>一</button>
<button>二</button>

原始换行 + 缩进完全保留

真正需要 preserve 的场景

<pre> 标签场景：代码内容中的前导空格、缩进必须保留。 
// 如果 code 变量包含前导空格
<pre>{{code}}</pre>

// condense 模式：前导空格可能丢失
// preserve 模式：空格完全保留
结论：大多数 UI 布局问题，用 CSS（flex/grid）解决比改 whitespace 更优。preserve 主要用于特殊内容渲染场景。

方案一：Flexbox（推荐）

最简洁、最健壮的布局方式，彻底消除内联元素间距问题。

.btn-group {
  display: flex;
}

按钮之间 无缝隙 — flex 布局消除了内联格式化上下文的间距

方案二：Grid 布局

.btn-group {
  display: grid;
  grid-auto-flow: column;
}

方案三：模板紧密排列

将内联元素写在同一行，避免换行产生空白：

<!-- 紧密排列，无换行 -->
<div><button>一</button><button>二</button></div>

<!-- 或用 Mustache 拼接 -->
<div>{{ btn1 }}<span>{{ btn2 }}</span></div>
缺点：代码可读性差，不易维护。

方案四：font-size: 0 技巧

.btn-group {
  font-size: 0;       /* 消除空格 */
}
.btn-group button {
  font-size: 14px;   /* 恢复字体大小 */
}
缺点：需要为子元素重置 font-size，且影响继承属性（letter-spacing 等）。

总结：如何选择？

方案 推荐度 适用场景
Flexbox ⭐⭐⭐ 强烈推荐 几乎所有场景
Grid ⭐⭐ 推荐 网格化布局
whitespace: preserve ⭐ 特定场景 pre 标签、严格空白格式
模板紧密排列 ⭐ 仅临时 临时修复，不推荐
