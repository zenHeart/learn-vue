关键结论：async 钩子中的 `await` 不会阻塞组件渲染。Vue 的生命周期调用不等待 async 函数完成，所以 mounted 会在 created 的 async 操作完成前执行。
生命周期执行顺序图
1. setup() / beforeCreate() / created() — 组件初始化
2. beforeMount() — 挂载前
3. mounted() — 组件渲染到 DOM，用户看到组件
4. async mounted 中的 await — 异步操作执行（不阻塞渲染）
5. async 操作完成 — 数据更新（可能触发 updated）
6. beforeUpdate() / updated() — 更新周期
7. beforeUnmount() / unmounted() — 销毁周期
1 Vue 调用 created → async 开始
2 Vue 调用 mounted → 组件渲染（不等待 async）
3 用户看到页面 → async 才刚开始执行
4 async 完成 → 数据更新（触发 updated）
关键结论速查
⚠️ 最重要的一点：Vue 的组件渲染管线是同步的。所有生命周期钩子无论是否 async，都不会阻塞组件渲染。
❌ 不要这样做： 
onMounted(async () => {
  this.data = await fetchData();
  // ⚠️ 此时用户已看到组件，但 data 还是旧值
});
✅ 推荐做法： 
// 方案1：v-if 控制渲染
const ready = ref(false);
onMounted(async () => {
  await fetchData();
  ready.value = true;
});

// 方案2：setup 顶层 await（需 Suspense）
const data = await fetchData();
📋 Vue 2 vs Vue 3 对比
Vue 2 `async created` 可用但不等待
Vue 3 setup ✅ 支持 async，配合 Suspense 等待
Vue 3 onMounted ⚠️ async 不等待，但不阻塞渲染
🔑 记忆口诀：
「钩子 async 不等待，setup 顶层才有效」
