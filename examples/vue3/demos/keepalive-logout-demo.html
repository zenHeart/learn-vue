场景 1：正常的 KeepAlive 行为

在正常路由切换时，使用 KeepAlive 缓存的组件不会触发 unmount，只会触发 deactivated。当再次访问时，会触发 activated 而不是 mounted。这展示了 KeepAlive 的核心价值：保持组件状态。

场景 2：退出登录时不清除缓存

这是默认行为。当用户退出登录时，如果只是简单地跳转到登录页，KeepAlive 缓存的组件实例仍然保留在内存中。这意味着组件的状态（如表单数据、用户信息等）仍然存在，可能导致安全隐患。

场景 3：退出登录时清除缓存

正确的做法是在退出登录时手动清除 KeepAlive 缓存。本演示展示两种方法：使用 v-if 控制和动态修改 include 数组。通过这些方法可以确保组件被完全销毁，防止数据泄露。

清除缓存的方法

方法1: v-if 控制

通过 v-if 控制 KeepAlive 的存在性，可以销毁所有缓存。

方法2: include/exclude 数组

动态设置 include 或 exclude 数组为空，可以清除特定缓存。

// 方法1: v-if 控制 <template> <KeepAlive v-if="isLoggedIn"> <component :is="Component" /> </KeepAlive> <component v-else :is="Component" /> </template> const handleLogout = async () => { isLoggedIn.value = false // KeepAlive 被移除，所有缓存销毁 await logoutAPI() router.push('/login') } // 方法2: 动态修改 include const cachedComponents = ref(['Dashboard', 'Profile']) const clearCache = () => { cachedComponents.value = [] // 清除所有缓存 }

场景 4：max 属性限制行为

KeepAlive 的 max 属性可以限制缓存组件的最大数量。当缓存数量超过 max 时，Vue 会使用 LRU（最近最少使用）策略销毁最旧的组件。本演示展示 max=2 时的行为。
