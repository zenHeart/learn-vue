🎯 v-model 与 change 事件冲突演示

❌ 错误示例：组件内部只触发 change

<!-- BadChild.vue --> <template> <select @change="handleChange"> <option value="a">A</option> <option value="b">B</option> </select> </template> <script> export default { methods: { handleChange(e) { // 错误：只触发 change this.$emit('change', e.target.value); } } } </script>
⚠️ 问题分析：
  • v-model 期望接收 update:modelValue 事件，但组件只触发 change
  • 外部绑定 @change 可能被 v-model 机制覆盖
  • 导致双向绑定失效或事件冲突

📋 事件名称对照表

框架v-model 绑定的事件常用表单事件
Vue 2inputchange, input
Vue 3update:modelValuechange, input
冲突场景同时绑定 @update:modelValue 和 @change 时可能冲突

✅ 方案一：同时触发两个事件（Vue 3）

<script setup> const emit = defineEmits(['update:modelValue', 'change']); const handleChange = (e) => { const value = e.target.value; // 同时触发 v-model 和 change emit('update:modelValue', value); emit('change', value); }; </script>

✅ 方案二：使用 .sync 修饰符（Vue 2）

<!-- Parent.vue --> <ChildComponent :value.sync="value" /> <!-- Child.vue --> this.$emit('update:value', newValue);

✅ 方案三：完全解耦手动绑定

<!-- 不使用 v-model，手动绑定两个事件 --> <ChildComponent :model-value="value" @update:model-value="value = $event" @change="onChange" />

🎯 最佳实践清单

  • 使用 emits 选项声明所有事件
  • 遵循 v-model 的 update:modelValue 语义
  • 避免在 update:modelValue 中重复触发 change
  • Vue 3 推荐使用 defineEmits 获得类型支持

📚 核心要点

1. v-model 本质

Vue 3: v-model = :model-value + @update:model-value

Vue 2: v-model = :value + @input

2. 冲突原因

  • 组件触发 change，但 v-model 期望 update:modelValue
  • 外部 @change 可能被 v-model 机制覆盖
  • 双向绑定失效或事件不触发

3. 解决方案

  • 推荐：同时触发 update:modelValue 和 change
  • 或完全解耦，使用手动绑定而非 v-model
  • 使用 emits 选项声明所有事件

🔑 决策树：选择哪种方案？

需要双向绑定 + 事件→ 同时触发两个事件
只需要双向绑定→ 只触发 update:modelValue
只需要事件处理→ 使用手动绑定，拆分 :model-value 和 @change
