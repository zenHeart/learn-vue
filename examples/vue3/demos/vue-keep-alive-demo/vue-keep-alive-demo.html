keep-alive 核心概念

缓存 vs 不缓存对比

行为无 keep-alive有 keep-alive
首次渲染created → mountedcreated → mounted
切换离开beforeUnmount → unmounteddeactivated
切换回来created → mountedactivated
状态保留❌ 丢失✅ 保留

基本语法

<!-- 缓存单个组件 --> <keep-alive> <MyComponent /> </keep-alive> <!-- 缓存多个动态组件 --> <keep-alive> <component :is="currentComponent" /> </keep-alive> <!-- 使用 include/exclude --> <keep-alive include="Home,About" exclude="User" :max="10"> <component :is="currentComponent" /> </keep-alive>

activated / deactivated 使用场景

export default { activated() { // 从缓存恢复时调用 // 适合：重启定时器、刷新数据 this.startTimer() this.fetchData() }, deactivated() { // 被放入缓存时调用 // 适合：暂停定时器、保存状态 this.stopTimer() this.saveState() } }

生命周期执行顺序

// 首次挂载 ComponentA created // ← A 创建 mounted // ← A 挂载 // 切换到 ComponentB deactivated // ← A 停用（被缓存） created // ← B 创建 mounted // ← B 挂载 // 切换回 ComponentA activated // ← A 激活（从缓存恢复） deactivated // ← B 停用 // 真正销毁时 beforeUnmount // ← A 即将销毁 unmounted // ← A 销毁

max 缓存限制

使用 :max 属性限制最大缓存实例数量，超出后移除最久未激活的实例（LRU 策略）。

// 最多缓存 3 个组件实例 <keep-alive :max="3"> <component :is="currentView" /> </keep-alive>

🎮 LRU 策略演示

max=3 时，切换顺序：A → B → C → A → B → D

LRU 策略说明

步骤缓存状态说明
1. 访问 A[A]A 被缓存
2. 访问 B[A, B]B 被缓存
3. 访问 C[A, B, C]C 被缓存，已满
4. 访问 A[B, C, A]A 已存在，更新为最新
5. 访问 D[C, A, D]移除最旧的 B（L R U）
