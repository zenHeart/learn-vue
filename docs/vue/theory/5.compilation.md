# 5. 编译优化

> **目标**：理解 Vue 模板编译优化策略，掌握 Patch Flags、静态提升、Block 等核心优化机制

---

## 5.1 编译概述

Vue 模板编译是将 `.vue` 文件中的 `<template>` 转换为 JavaScript 渲染函数的过程：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Vue 模板编译流程                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌─────────────┐                                                  │
│   │   .vue      │   <template>                                     │
│   │   文件      │   <div :class="cls">{{ msg }}</div>              │
│   └──────┬──────┘                                                  │
│          │                                                          │
│          ▼ Compile (编译)                                           │
│   ┌─────────────┐                                                  │
│   │  Render Fn  │   function render(ctx) {                        │
│   │  (渲染函数)  │     return _createElement('div', {              │
│   │              │       class: _normalizeClass(ctx.cls)           │
│   │              │     }, [ctx.msg])                               │
│   └─────────────┘   }                                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 编译方式

| 方式 | 说明 | 使用场景 |
|------|------|----------|
| **构建时编译** | 模板提前编译为渲染函数 | 生产环境（推荐） |
| **运行时编译** | 浏览器中动态编译模板 | 需要动态模板的场景 |

## 5.2 静态提升 (Static Hoisting)

### 问题

```html
<!-- 每次渲染都创建新的 VNode -->
<template>
  <div>
    <h1>静态标题</h1>        <!-- 没必要每次重新创建 -->
    <p>静态内容</p>          <!-- 没必要每次重新创建 -->
    <span>{{ dynamic }}</span>
  </div>
</template>
```

### 优化后

```javascript
// 静态节点被"提升"到渲染函数外部
const _hoisted_1 = _createElementVNode("h1", null, "静态标题")
const _hoisted_2 = _createElementVNode("p", null, "静态内容")

function render(ctx) {
  return _createElement("div", null, [
    _hoisted_1,           // 复用已创建的 VNode
    _hoisted_2,           // 复用已创建的 VNode
    _createElement("span", null, [ctx.msg])  // 动态节点
  ])
}
```

### 效果

- 减少 VNode 创建开销
- 减少内存分配
- Diff 时跳过静态节点

## 5.3 Patch Flags (补丁标志)

### 问题

```html
<!-- 编译前不知道要更新什么 -->
<div :class="{ active }"></div>
<input :value="value">
```

### 编译后

```javascript
// Vue 知道这是 CLASS 更新
_createElementVNode("div", {
  class: _normalizeClass({ active: _ctx.active })
}, null, 2 /* CLASS */)

// Vue 知道这是 VALUE 更新
_createElementVNode("input", {
  value: _ctx.value
}, null, 64 /* VALUE */)
```

### Patch Flag 列表

| Flag | 值 | 说明 |
|------|-----|------|
| `TEXT` | 1 | 文本内容更新 |
| `CLASS` | 2 | class 更新 |
| `STYLE` | 4 | style 更新 |
| `PROPS` | 8 | props 更新（不包括 class/style） |
| `FULL_PROPS` | 16 | 含有动态 key 的 props |
| `HYDRATION_EVENTS` | 32 | 事件绑定 |
| `STABLE_FRAGMENT` | 64 | 稳定结构的 Fragment |
| `KEYED_FRAGMENT` | 128 | 带 key 的 Fragment |
| `UNKEYED_FRAGMENT` | 256 | 不带 key 的 Fragment |
| `NEED_PATCH` | 512 | 需要打补丁 |
| `DYNAMIC` | 768 | 动态节点（有 slot） |
| `DEV_ROOT_FRAGMENT` | 1024 | 开发模式根 Fragment |

### 运行时检查

```javascript
// 使用位运算快速判断
if (vnode.patchFlag & PatchFlags.CLASS) {
  // 只更新 class
}
```

## 5.4 Block (块)

### 概念

Block 是模板中**结构稳定**的部分：

```html
<!-- 整个 div 是一个 Block，因为没有 v-if/v-for -->
<div>
  <div>static</div>
  <span>{{ dynamic }}</span>
</div>
```

### 编译后

```javascript
// createElementBlock 创建一个"块"
function render() {
  return (_openBlock(), _createElementBlock("div", null, [
    // 静态节点不追踪
    _createElementVNode("div", null, "static"),
    // 动态节点被追踪
    _createElementVNode("span", null, _toDisplayString(_ctx.dynamic), 1 /* TEXT */)
  ]))
}
```

### v-if/v-for 创建新 Block

```html
<div>                    <!-- Block A -->
  <div v-if="show">      <!-- Block B (新块) -->
    <span>{{ msg }}</span>
  </div>
</div>
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Block 树结构                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   Block A (根块)                                                    │
│   ├── 静态子节点                                                   │
│   │   └── ...                                                      │
│   └── Block B (v-if 创建)                                          │
│       └── 动态节点                                                  │
│           └── ...                                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 5.5 树形扁平化 (Tree Flattening)

### 问题

```html
<div>
  <div>static1</div>
  <div>static2</div>
  <div>static3</div>
  <div>{{ dynamic }}</div>
  <div>
    <span>{{ nested }}</span>
  </div>
</div>
```

### 优化后的扁平结构

```javascript
// 只追踪动态节点，扁平化存储
const vnode = createElementBlock("div", null, [
  // 扁平数组：只有动态节点
  createElementVNode("span", null, dynamic, 1 /* TEXT */),
  createElementVNode("span", null, nested, 1 /* TEXT */)
])
```

### 效果

- 渲染时只需遍历动态节点
- 跳过所有静态子树
- 大幅减少 Diff 遍历节点数

## 5.7 事件监听器缓存

### 优化前

```html
<button @click="handleClick">Click</button>
```

```javascript
// 每次渲染都创建新的事件处理函数
_createElementVNode("button", {
  onClick: handleClick  // 每次都是新引用
}, "Click")
```

### 优化后（开启缓存）

```html
<button @click="handleClick">Click</button>
```

```javascript
// 事件处理函数被缓存
const _cache = {}
function render(ctx) {
  return _createElementVNode("button", {
    onClick: _cache[0] || ( _cache[0] = ($event, ...args) => handleClick($event, ...args) )
  }, "Click")
}
```

### 对比

| 场景 | 未缓存 | 缓存后 |
|------|--------|--------|
| 父组件渲染 | 子组件所有事件重新绑定 | 跳过事件绑定 |
| Diff 比较 | 每次都是新函数 | 相同引用 |

## 5.8 SSR 优化 (Hydration)

### 问题

传统 SSR Hydration 需要遍历整个 VNode 树：

```javascript
// 未优化：需要验证每个节点
function hydrate(node, vnode) {
  // 逐个节点验证和激活
  hydrate(node.firstChild, vnode.children[0])
  hydrate(node.nextSibling, vnode)
}
```

### 优化后

```javascript
// 利用 Patch Flag 跳过静态节点
function hydrate(node, vnode) {
  if (vnode.patchFlag > 0) {
    // 快速路径：直接激活
    activate(node, vnode)
  } else {
    // 慢速路径：遍历子节点
    hydrateChildren(node, vnode.children)
  }
}
```

### 效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| Hydration 时间 | O(n) | O(dynamic nodes) |
| 需要激活的节点 | 全部 | 仅动态节点 |
| SSR 优势 | - | 接近 CSR 性能 |

## 5.9 实际例子

### 查看编译输出

使用 [Vue Template Explorer](https://template-explorer.vuejs.org/) 查看编译结果：

```html
<!-- 输入 -->
<div id="app">
  <h1 class="title">{{ message }}</h1>
  <button @click="handleClick">Click</button>
  <ul>
    <li v-for="item in items" :key="item.id">{{ item.text }}</li>
  </ul>
</div>
```

### 编译后（简化）

```javascript
// 静态提升
const _hoisted_1 = _createElementVNode("h1", { class: "title" }, null, -1 /* UNKEYED_FRAGMENT */)

// Block 结构
function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("div", { id: "app" }, [
    // CLASS patch flag
    _hoisted_1,
    _toDisplayString(_ctx.message),
    // HYDRATION_EVENTS patch flag
    _createElementVNode("button", { onClick: _ctx.handleClick }, "Click", 8 /* PROPS */, ["onClick"]),
    // KEYED_FRAGMENT
    _createElementVNode(_Fragment, null, _renderList(_ctx.items, (item) => {
      return _createElementVNode("li", { key: item.id }, _toDisplayString(item.text), 1 /* TEXT */)
    }), 128 /* KEYED_FRAGMENT */)
  ], 64 /* STABLE_FRAGMENT */))
}
```

## 5.10 编译选项

### hoistStatic（静态提升）

```javascript
import { compile } from 'vue'

const { code } = compile(template, {
  mode: 'module',           // 模块模式（支持静态提升）
  hoistStatic: true,       // 开启静态提升（默认 true）
  cache: {},                // 事件处理函数缓存
})
```

### Custom Directives 编译

```javascript
const { code } = compile(template, {
  mode: 'module',
  prefixIdentifiers: true,
  nodeModules: ['vue'],     // 允许在模板中使用 node_modules
})
```

## 5.11 性能优化建议

### 1. 使用 v-show 代替 v-if（稳定结构）

```html
<!-- ❌ v-if 切换时重建 DOM，破坏 Block 结构 -->
<div v-if="show">
  <ComplexComponent />
</div>

<!-- ✅ v-show 不破坏结构 -->
<div v-show="show">
  <ComplexComponent />
</div>
```

### 2. 合理使用 key

```html
<!-- ❌ 无 key 导致无法复用 DOM -->
<li v-for="item in items">{{ item.name }}</li>

<!-- ✅ 有 key 利于 Diff 优化 -->
<li v-for="item in items" :key="item.id">{{ item.name }}</li>
```

### 3. 避免不必要的响应式

```javascript
// ❌ 大量数据不需要响应式
const data = reactive(veryLargeArray)

// ✅ 拆分粒度
const visibleItems = computed(() => veryLargeArray.slice(0, 10))
```

### 4. 使用 v-memo 缓存子树

```html
<!-- 仅在 items 变化时更新，title 变化不更新 -->
<div v-memo="[items]">
  <span>{{ title }}</span>
  <li v-for="item in items">{{ item }}</li>
</div>
```

## 5.12 关键知识点

| 优化技术 | 说明 | 效果 |
|----------|------|------|
| **静态提升** | 静态节点提取到渲染函数外 | 减少 VNode 创建 |
| **Patch Flags** | 编译时标记更新类型 | 运行时快速判断 |
| **Block** | 稳定结构的模板块 | 跳过 Diff |
| **树形扁平化** | 只追踪动态节点 | 减少遍历 |
| **事件缓存** | 缓存事件处理函数 | 减少绑定开销 |
| **SSR Hydration** | 部分激活 | 提升首屏性能 |
