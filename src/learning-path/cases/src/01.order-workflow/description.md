# 订单审核：从交互到状态契约

## 目标与起点

你能实现创建与审核流程，拒绝非法金额、错误角色、旧版本和重复审核，并解释前端校验与服务端鉴权的边界。 本例是基于公开技术机制设计的教学任务，不是某企业内部项目。前置：函数、对象、Promise，以及 Vue 的基本模板与状态绑定。先独立完成，再查看“显示提示”中的参考解法。

## 先预测，再运行

操作员能否审核？同一版本提交两次会怎样？修改 list() 返回值会不会影响内部状态？

在编辑器中修改 `model.js`，用界面的实际结果核对预测。保留一段自己的解释；照着参考解法完成的尝试只算练习，不算无提示通过。

## 机制与常见错误

输入状态与业务状态应分开；动作先校验不变量，再产生新的状态快照。引用返回的可变对象会绕开业务动作。

需要反驳的误解：把按钮隐藏就能防越权；把字段复制到 UI 就是不可变快照。
